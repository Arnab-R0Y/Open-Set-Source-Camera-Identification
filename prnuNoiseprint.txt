## 1) One-paragraph summary (the big idea)

* **PRNU** is a *device-level* fingerprint (comes from sensor pixel non-uniformity) and is excellent at distinguishing *individual devices* when there is plenty and high-quality data. **Noiseprint** is a *model-level* fingerprint extracted by a CNN trained in a Siamese fashion; it highlights model-specific artifacts and is much stronger and more robust (works better on small crops and with few images) but *doesn’t* distinguish devices of the same model. The paper’s core idea is to **combine both pieces of evidence** (PRNU device-specific evidence and Noiseprint model evidence) to get a more robust source identification, especially in challenging conditions (small crops, few reference images, JPEG compression).

## 2) Background & core concepts (detailed)

### PRNU — model, extraction and matching (what & how)

* **Image model (simplified multiplicative model):**
  ( I = (1 + K) I_0 + \eta )
  where (I) is observed image, (I_0) scene radiance, (K) PRNU factor, and (\eta) other noise. 
* **Residual extraction:** for each image (I_{i,n}) from device (i), compute a denoised image (f(I_{i,n})) and get residual
  (W_{i,n} = I_{i,n} - f(I_{i,n})). Typical denoisers used in the literature: BM3D, wavelet shrinkage, or strong CNN denoisers; the denoiser’s purpose is to remove scene content and leave sensor noise. 
* **PRNU estimator (reference fingerprint):** average residuals across (N) images
  (\hat K_i = \frac{1}{N}\sum_{n=1}^N W_{i,n}) (or ML variants). After averaging, further filtering is applied to remove periodic artifacts (e.g., subtract row/column means and Wiener filtering in the DFT domain) so the fingerprint better represents sensor PRNU rather than JPEG/model periodicities. 
* **Matching (PRNU distance):** compute normalized cross-correlation (NCC) between a test residual (W_m) and reference PRNU (K_i):
  (\mathrm{NCC}(W_m, K_i) = \frac{\langle W_m, K_i\rangle}{|W_m| ,|K_i|}). The PRNU pseudo-distance used in the paper is
  (\mathrm{D_{PRNU}}(i,m) = 1 - \mathrm{NCC}(W_m, K_i)). Small values → likely same device. 

### Noiseprint — what it is and how it’s obtained

* **Noiseprint definition:** an image-sized pattern emphasizing *camera-model-specific* artifacts (demosaicking, compression, in-camera processing), with scene content suppressed, extracted by a CNN (the authors call the function (\phi(\cdot))). Unlike PRNU, noiseprint is **model-level** (same model → similar noiseprints, different devices of same model → mostly identical noiseprints). 
* **Training strategy (Siamese CNN):** two identical CNN branches take pairs of patches; pairs are labeled *positive* if they come from the same camera **model** and same spatial position, *negative* otherwise. A loss enforces that outputs from positive pairs are similar — so the network learns to highlight model artifacts and suppress scene content. After training, given an image (I), the network outputs (\phi(I)), the noiseprint. 
* **Noiseprint reference:** for model (M_i), average noiseprints from images of that model to obtain (R_i = \frac{1}{N}\sum_{n}\phi(I_{i,n})).
* **Noiseprint distance (DNP):** measure MSE between test noiseprint and model reference:
  (\mathrm{D_{NP}}(i,m) = \mathrm{MSE}(R_i, \phi(I_m))). Small values → test image likely from model (i).

## 3) WHY combine PRNU + Noiseprint? (intuition + evidence)

* **Complementarity:**

  * PRNU → strong for *device* identification but **weak** when reference has few images, or test crop is small, or image is compressed.
  * Noiseprint → strong for *model* identification, robust for small patches and few images, but **cannot** resolve which specific device within that model took the image.
* **Risk of hierarchical approach:** if you first use noiseprint to choose a model and then restrict PRNU search to that model, an error in model selection may eliminate the correct device. So the paper proposes **joint fusion** — combine the two distances (DPRNU and DNP) into one decision metric, rather than strict hierarchical filtering. 

---

## 4) How they combine — the three fusion strategies (math + intuition)

They treat the binary hypothesis test for device (i) and image (m):

* (H_0): image not from device (i)
* (H_1): image from device (i)

They compute the 2D vector ((\mathrm{D_{PRNU}}, \mathrm{D_{NP}})) and combine it using:

1. **Linear SVM (score from oriented distance to hyperplane)**

   * Train a **linear** SVM on labeled training pairs ((D_{PRNU}, D_{NP})) to separate (H_1) and (H_0). The signed distance to the hyperplane is used as a final score; choose device with max score or threshold for verification. (Simple, data-driven, linear decision boundary.) 

2. **Likelihood Ratio Test (LRT)** — *statistical model*

   * Model the joint vector as Gaussian under both hypotheses:
     ((D_{PRNU}, D_{NP}) \sim \mathcal N(\mu_0, \Sigma_0)) under (H_0) and (\mathcal N(\mu_1, \Sigma_1)) under (H_1).
   * Estimate (\mu_0,\Sigma_0,\mu_1,\Sigma_1) from training data, then compute log-likelihood ratio:
     (\Lambda = \log \frac{\mathcal N(\mathbf{d}\mid\mu_1,\Sigma_1)}{\mathcal N(\mathbf{d}\mid\mu_0,\Sigma_0)}).
   * Two estimation modes: ML (classical) and robust estimation using **Minimum Covariance Determinant (MCD)** to handle outliers/ non-Gaussianity (especially useful under JPEG/compression).

3. **Fisher’s Linear Discriminant (FLD)** — analytic linear projection

   * Finds direction (w) maximizing class separation:
     (w_{\text{opt}} \propto (\Sigma_1 + \Sigma_0)^{-1}(\mu_1 - \mu_0)).
   * Score is projection (s = w_{\text{opt}}^\top [D_{PRNU}, D_{NP}]^\top).
   * Again both ML and robust covariance estimation can be used; the robust FLD (r-FLD) often performed best in compressed scenarios.

**Important note:** the two distances are used *as features* — scaling/normalization matters (z-scoring / variance normalization) before classifier training.

## 5) Experimental setup — datasets, scenarios, evaluation

* **Datasets used:**

  * Noiseprint CNN trained on a large dataset from *dpreviewer.com* (authors collected ~625 camera models — 600 train / 25 val). 
  * Classifier parameter estimation (fusion models) trained on **VISION** dataset (29 models). 
  * Final testing performed on **Dresden** dataset (25 models; authors selected 18 models with ≥2 devices → total 66 devices). This ensures separation between training and testing sets. 
* **Operating conditions varied in experiments:** crop size (d \times d) ∈ {64, 256, 1024}, number of reference images (N) ∈ {1, 10, 100}, and JPEG compression (uncompressed, QF=90, QF=80). They report closed-set accuracy and open-set ROC / AUC.
* **Training/testing splits in experiments:** For each camera in Dresden they used 100 images to estimate references and 50 images for testing (varied N for experiments via subsampling/repetition where N < 100).

## 6) Key experimental findings (what actually improved)

* **PRNU-only is excellent in ideal conditions** (large crops, many ref images), but degrades quickly for small crops and small (N). Noiseprint-only is **never** as good for device ID (because of device indistinguishability within the same model) but is **very stable** across all conditions and still discriminative for model differences.
* **Fusion yields large gains in challenging cases:** e.g.,

  * For (d=1024, N=1): PRNU-only accuracy ≈ 0.649 → ideal (perfect model) upper bound 0.793; fusion (FLD) achieves ≈ 0.751. This is a substantial improvement where PRNU alone is unreliable. 
  * For small crops ((d=64)) and scarce data, fusion often increases accuracy dramatically (see tables in paper). 
* **Open-set verification (AUC)**: fusion (FLD or LRT) achieves AUCs usually close to the “ideal” reference and significantly higher than PRNU-only in hard cases (AUC often > 0.93 even when PRNU alone is poor). 
* **Compression:** JPEG lowers both PRNU and noiseprint performance, but **robust** methods (r-LRT, r-FLD with MCD covariance estimation) perform better under compression than ML-based estimators. Fusion remains beneficial.

## 8) Practical implementation notes (how to reproduce / integrate into your code)

Below are **precise, actionable steps** you can implement using your existing `getNoiseprint` function and your PRNU extraction:

### PRNU estimation (reference) — recommended steps

1. For each reference image (I_{i,n}): compute residual
   `W = I - denoise(I)` — use **BM3D** (best), or a strong CNN denoiser; Gaussian blur is too weak for robust PRNU estimation in real use.
2. Average residuals: `K_i = mean(W_{i, :}, axis=0)` (or ML-weighted average).
3. Remove periodic artifacts:

   * subtract row and column means from `K_i` (paper recommends this).
   * apply Wiener filtering in DFT domain (to reduce JPEG/model periodicities). The paper references Wiener filtering in the DFT for PRNU cleanup. 

### Test-time residual and DPRNU

* Compute test residual `W_m = I_m - denoise(I_m)`.
* Flatten and compute NCC:

```python

ncc = num / den
Dprnu = 1.0 - ncc
```

### Fusion / classification (practical code suggestions)

* **SVM (linear):** `sklearn.svm.SVC(kernel='linear', probability=True)` → train on labeled pairs `(Dprnu, Dnp)` with labels `H1/H0`. Use signed distance as score.
* **LRT:** estimate `mu0, Sigma0, mu1, Sigma1` from training pairs. Compute log-likelihood ratio using multivariate Gaussian pdf (use `scipy.stats.multivariate_normal.logpdf`). For robust covariance, use `sklearn.covariance.MinCovDet` (MCD). 
* **FLD:** compute `w = np.linalg.inv(Sigma0 + Sigma1) @ (mu1 - mu0)` and score `s = w.T @ [Dprnu, Dnp]`. The robust FLD uses covariances from MCD.

## 9) Limitations & failure modes (what to watch out for)

* **Noiseprint cannot identify different devices of the same model** — it’s model-specific. So fusion helps but is not a silver bullet. Relying solely on noiseprint can’t solve device-level ID. 
* **Wrong model identification risk** if using hierarchical pipeline — this is why the paper advocates joint fusion instead of hard filtering. 
* **JPEG compression and heavy post-processing** reduce both signals; robust covariance estimation and robust fusion methods help but extreme compression remains difficult. 
* **Training-data dependence**: fusion parameters (SVM, LRT means/covariances, FLD weights) must be learned for the *specific operating conditions* (patch size, JPG QF, #ref images). The paper trains separate estimators per scenario.

## 10) Concrete short code sketches you can drop into your pipeline

(You already have `getNoiseprint`. Below are **small** snippets for distances & fusion.)

**DPRNU (NCC-based)**

```python
import numpy as np

def compute_dprnu(Wm, Ki):
    # Wm, Ki: 2D numpy arrays (same size)
    w = Wm.ravel()
    k = Ki.ravel()
    num = np.dot(w, k)
    den = np.linalg.norm(w) * np.linalg.norm(k) + 1e-12
    ncc = num / den
    return 1.0 - ncc
```

**DNP (MSE-based)**

```python
def compute_dnp(phi_im, R_i):
    # phi_im and R_i are 2D numpy arrays
    return np.mean( (phi_im - R_i)**2 )
```

**FLD weight calculation (training)**

```python
def train_fld(Dprnu_train, Dnp_train, labels):
    # Dprnu_train, Dnp_train shape (N_samples,)
    X = np.vstack([Dprnu_train, Dnp_train]).T
    X1 = X[labels==1]
    X0 = X[labels==0]
    mu1 = X1.mean(axis=0); mu0 = X0.mean(axis=0)
    S1 = np.cov(X1, rowvar=False); S0 = np.cov(X0, rowvar=False)
    W = np.linalg.inv(S0 + S1) @ (mu1 - mu0)
    return W, mu0, mu1, S0, S1

def fld_score(W, dprnu, dnp):
    return W.dot(np.array([dprnu, dnp]))
```

(For robust covariances use `sklearn.covariance.MinCovDet`.)
